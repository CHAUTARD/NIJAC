## Project overview

NIJAC is a PHP/MySQL web app for managing and nominating table-tennis referees (Juges-Arbitres, JA) for the Normandy League. Stack: PHP 8.2+, CodeIgniter 4, MySQL/MariaDB, Bootstrap 5, jQuery 3, no front-end build step.

The application is entirely implemented in `ci4/` (CodeIgniter 4). There is no more legacy stand-alone-PHP-page app — it was fully replaced by the CI4 port (see `git log` around "Version avec Ci4"). The repository root still holds shared, framework-agnostic pieces the CI4 app depends on: `config/` (`db.php`, `app_config.php`, `helpers.php`), `Classes/` (`Obfuscator.php`, `SecurePasswordHasher.php`, `Distance.php`), and `asset/` (CSS/JS served straight from the root, not from `ci4/public/`).

### FFTT API client

All FFTT calls go through `App\Libraries\FfttRawClient` (`ci4/app/Libraries/FfttRawClient.php`), instantiated via `getFfttRawClient()` (config/app_config.php), authenticated with `getFfttAppId()`/`getFfttAppKey()` (config/db.php, ROT47-decoded from `.env`). Plain PHP cURL, no Composer runtime dependency — production only has FTP access (no Composer, no shell), so this was a deliberate choice: any future change to this feature deploys like any other PHP file, no `vendor/` sync step.

Two ways to call it:

- **7 typed convenience methods** — `listClubsByDepartement()`, `retrieveClubDetails()`, `listOrganismes()`, `listEpreuves()`, `listEquipesByClub()`, `retrieveJoueurDetails()`, `listJoueursByClub()` — cover every FFTT call actually used by production screens (EN11, EN27, EA81, EA82, EA83). Each returns a plain associative array (or array of arrays) with the raw FFTT field names (e.g. `numero`, `nom`, `nomsalle`, `libequipe`) — no typed model objects.
- **`request(string $action, array $params = []): array`** — for any other raw endpoint: `xml_division`, `xml_result_equ` (poules/rencontres by division ID or `cx_poule`), `xml_chp_renc`, `xml_licence` (base SPID, distinct from `xml_licence_b`), or any field a convenience method doesn't surface (e.g. `xml_club_detail` returning multiple salles for one club — see `SalleController::ffttSync()`). `lastUrl()`/`lastHttp()`/`lastRaw()` expose the last request's details for diagnostics (see EA96).

Previously used the composer package `alamirault/fftt-api` (typed facade + Guzzle 6.x, an EOL branch with known CVEs) and, before that, `Classes/FfttApi.php` (raw cURL, a different `serie`/app-key signing scheme) — both removed. EA96 (FfttTestController, `testViaLibrary()`) only exercises the 7 production-used methods; it no longer covers the old facade's diagnostic-only surface (classement, historique, parties, Elo-style virtual points, regex-parsed rencontre details, actualités...), none of which backed a real screen.

## Running locally

No build step. Requires WAMP (Apache + MySQL on port 3307).

```bash
composer install          # root: PhpSpreadsheet + PHPMailer, used by config/app_config.php
cd ci4 && composer install # ci4/: CodeIgniter 4 framework itself
```

Access via `http://nijac/` — a dedicated WAMP vhost whose `DocumentRoot` is this folder directly (see `httpd-vhosts.conf` and the Windows `hosts` file), matching `app.baseURL` in `ci4/.env` (`http://nijac/`). Do **not** use `http://localhost/NIJAC/` (default vhost, NIJAC as a subfolder): `Config\App::$baseURL` has no path segment, so every `site_url()`/`base_url()` link generated while browsing under that host is wrong (wrong host under the default vhost, or wrong path if the host is added to `allowedHostnames`) — CodeIgniter's `SiteURI` only swaps the host for allowed hostnames, never the base path, so the two access methods can't both work against a single static `baseURL`. In production the app is deployed under a path (`https://www.ligue-normandie-tt.fr/nijac/`), so `ci4/.env`'s `app.baseURL` there must include that path — that `.env` is a separate file edited directly on the server (FTP-only deploy, see below), not the one in this repo. The root `.htaccess` transparently forwards everything to `ci4/public/index.php` (the CI4 front controller) except real files/folders (`asset/`, `img/`, `logs/`, `ci4/` itself), which are served as-is — except `.env*` (any location), `SQL/` (DB backups, read only server-side by `CleanController`) and `Importation/` (import drop folder, read/written only server-side), all explicitly denied since nothing in the app serves them over HTTP and they contain secrets/PII. No `RewriteBase` is hard-coded, so the same `.htaccess` works whether this folder is a vhost docroot (WAMP) or a subfolder (production).

The DB schema migrations run via `config/app_config.php → initTableConfiguration()`, no CI4 migration files are used. Only `DbAdminController` (EA98) calls it, so a new column/table gets created the first time an admin loads the EA98 screen after deploying a change — not automatically on every page load like before. The former per-controller inline `DESCRIBE`/`ALTER TABLE ADD COLUMN` self-healing checks (e.g. `DesiderataClubController` for `salle.Cp`, `JugearbitreController::ensureFfttColumns()`) have been removed: every column is assumed present in the DB. Adding a new column now means an explicit `ALTER TABLE` on each environment (or via EA98). Two exceptions remain: `ajouterValeurEnum()` still extends the `messagerie.Type` `ENUM` at runtime (roles are no longer an ENUM: tables `role` / `utilisateur_role`), and a handful of import controllers still create their own indexes/FKs and `CREATE TABLE IF NOT EXISTS competition_regionale` (with its seed) inside a guarded `try/catch`.

No test suite exists for the application itself (`ci4/tests/` is the untouched CodeIgniter starter scaffold).

## Architecture

### Request lifecycle

Standard CodeIgniter 4 MVC: `ci4/app/Config/Routes.php` maps each URL to a `Controller::method`. Every controller extends `BaseController` and requires the legacy shared config files itself in its constructor (see below) — there's no bootstrap/autoloaded global include. Most screens are still dual-mode in spirit: one `index()` action renders the HTML view, and sibling actions (`data`, `store`, `update`, `delete`, ...) serve AJAX, mirroring the old "one file, `$action` dispatch" pattern but split into real controller methods and real routes instead of a single `$_POST['action']` switch.

### Key shared files (root, outside `ci4/`)

| File | Role |
|---|---|
| `config/db.php` | PDO singleton (`getPDO()`), env detection (WAMP vs production via `NIJAC_ENV` or the request host: local host / CLI = dev, any other host = production; single `.env`), `rot47()` decoding of DB/SMTP/FFTT secrets from `.env` |
| `config/app_config.php` | DB migrations (`initTableConfiguration()`), all config helpers (`getConfig()`, `getDeptActifs()`, `getDepartementsAutorises()`), PHPMailer factory (`getNijacMailer()`), rate-limit helpers |
| `config/helpers.php` | Misc shared helpers used by a handful of controllers (adresse/commune/salle lookups) |
| `Classes/Obfuscator.php` | Bi-directional integer ↔ 8-char token (bcmath + Knuth multiplicative hash, seed = `OBFUSCATOR_SEED = 167` + secret pepper from `getObfuscatorPepper()`) — used to expose JA IDs in public URLs without leaking real PKs |
| `Classes/SecurePasswordHasher.php` | bcrypt wrapper — use `::hash($plain)` and `::verify($plain, $hash)` |
| `Classes/Distance.php` | GPS distance calculation between two lat/lon points |
| `tools/rot47.php` | Standalone CLI (`php tools/rot47.php valeur`) to pre-compute a ROT47-encoded value to paste into `.env` — not called by the app itself; the `rot47()` function it demonstrates is duplicated inside `config/db.php`, which the app does use |

Every CI4 controller pulls in `config/db.php` (and most also `config/app_config.php`, some also `config/helpers.php`) via `require_once __DIR__ . '/../../../config/xxx.php';` in its constructor — that relative path is `ci4/app/Controllers/` → repo root.

### Key CI4 files

| File | Role |
|---|---|
| `ci4/app/Config/Routes.php` | All routes; each screen's block is commented with its `EXXXX` code and access rule |
| `ci4/app/Config/Filters.php` | Filter aliases (`auth`, `adminauth`, `csrf`, ...) and globals — `csrf` filter is applied globally to all POST/PUT/PATCH/DELETE |
| `ci4/app/Config/Security.php` | CSRF config — `csrfProtection = 'cookie'` (double-submit, no CI4 session dependency), `regenerate = false` (stable token per session, screens fire multiple sequential AJAX POSTs), header name `X-CSRF-Token` |
| `ci4/app/Config/Database.php` | CI4 DB config — does **not** define its own credentials; `require_once`s the root `config/db.php` and copies `DB_HOST`/`DB_USER`/`DB_PASS`/`DB_NAME`/`DB_CHARSET`/`DB_PORT` into `$default` (single source of truth for DB config stays in the legacy file) |
| `ci4/app/Filters/AdminAuth.php` | Redirects to `login` unless `$_SESSION['utilisateur']['is_admin']` is true. Starts the session with **native** `session_start()`, not CI4's Session service — CI4's `FileHandler` names session files `PHPSESSID<id>` (vs PHP's own `sess_<id>`), so using CI4's service would silently stop sharing sessions with anything reading the raw `$_SESSION` global the same way the old app did |
| `ci4/app/Filters/Auth.php` | Redirects to `login` unless the role is Administrateur or Nominateur (or `is_admin`), or one of the extra roles listed in the route's filter arguments (e.g. `auth:CRA Convoc`) — the `JA` role is never a default, so it is refused everywhere except `changer-mot-de-passe` (`auth:…,JA`) |
| `ci4/app/Filters/JaAuth.php` | `jaauth`: role `JA` ONLY (Administrateur refused — the screens show one specific JA's data), plus a valid fiche from `idJaCompteSession()` (pure JA account: its `utilisateur.Id_Ja` via `idJaDuCompteJa()` — pre-EA98 fallback: fiche whose `Id_JA` equals the session `id`; mode JA: `id_ja` = the account's `utilisateur.Id_Ja`, re-read); otherwise session emptied (new id) and redirect to `login` with `MSG_COMPTE_JA_SANS_FICHE`; a SQL failure during that check (`idJaCompteSession($pdo, true)` rethrows) is logged, the session is kept and a 503 + `Retry-After` is returned (JSON `{ok:false}` for AJAX/POST) |
| `ci4/app/Controllers/BaseController.php` | Empty CI4 starter base — no shared NIJAC logic lives here (that's why every controller requires the config files itself) |

### View / header convention

There is no shared header/layout partial (no equivalent of the old `includes/page_header.php`). Each view file (`ci4/app/Views/xxx_index.php`) is a full standalone HTML document that inlines its own `<head>`, its own `#page-header` markup (title, `EXXXX` badge, back link via `site_url(...)`), and its own `<style>` block. New screens should copy the header block from an existing view (e.g. [region_index.php](ci4/app/Views/region_index.php)) rather than trying to factor it out.

The CSRF token is exposed via `<meta name="csrf-token" content="<?= csrf_hash() ?>">` in every view's `<head>`, and `asset/js/nijac-csrf.js` reads that meta tag to inject the `X-CSRF-Token` header on jQuery AJAX calls.

### AJAX pattern

All AJAX endpoints return `['ok' => true/false, ...]` as JSON (`$this->response->setJSON(...)`). The JS side always checks `r.ok`. CSRF verification is handled globally by CI4's `csrf` filter (see `Config\Filters`) — controllers don't call anything themselves, unlike the old per-endpoint `csrfVerify(true)`.

### Session structure

Still plain PHP session (native `session_start()`/`$_SESSION`, not CI4's Session service — see `AdminAuth.php` above):

```php
$_SESSION['utilisateur'] = [
    'id'             => int,       // Id_Utilisateur
    'login'          => string,
    'nom'            => string,
    'prenom'         => string,
    'role'           => 'Administrateur' | 'Nominateur' | 'CSR' | 'Defiscalisateur' | 'CRA Convoc' | 'JA', // rôle PRINCIPAL
    'roles'          => string[],  // tous les rôles du compte, principal en tête (puis role.Priorite)
    'is_admin'       => bool,      // 'Administrateur' ∈ roles
    'id_departement' => string,    // e.g. '76'
    'change_login'   => bool,      // forces password change on next login
    'email'          => string,    // Utilisateur.Email — Reply-To + Cc prefill in Centre d'envoi (EN15)
    'pwd_version'    => ?int,      // Utilisateur.PwdVersion at login (null before EA98 / old sessions)
    'verifie_le'     => int,       // timestamp of the last DB revalidation
    // ONLY in « mode JA » (non-JA account with a linked fiche, POST changer-compte action=ja) — 'id' stays the account's Id:
    'mode_ja'        => true,
    'id_ja'          => int,       // utilisateur.Id_Ja of the account (fiche ja), re-read in DB
    'origine_role'   => string,    // account's principal role at switch time ('role' is then 'JA', 'roles' ['JA'], 'is_admin' false)
    'origine_roles'  => array,     // account's roles at switch time (compared by the revalidation)
];
```

**Multi-rôles.** Un compte a un ou plusieurs rôles : table de référence `role` (`Id_Role` INT UNSIGNED AUTO_INCREMENT PK, `Nom` VARCHAR(30) UNIQUE = nom manipulé par le code — `Administrateur`, `Nominateur`, `CSR`, `CRA Convoc`, `Defiscalisateur`, `JA` —, `Libelle`, `Priorite`, `RouteMenu` = route du menu d'accueil ; amorcée depuis la constante `ROLES_REFERENCE` ; priorités Administrateur 1, Nominateur 2, CRA Convoc 3, CSR 4, Defiscalisateur 5, JA 6 — CRA Convoc / CSR réappliquées à chaque EA98 par `PRIORITES_ROLES_FORCEES`) + liaison `utilisateur_role` (`Id_Utilisateur`, `Id_Role` → `role.Id_Role`, `estPrincipal` ; PK `(Id_Utilisateur, Id_Role)`, index `Id_Role`, FK utilisateur `ON DELETE CASCADE`, FK role `ON DELETE RESTRICT`, repli sans FK). **Le code PHP ne manipule que des NOMS de rôles** : les fonctions ci-dessous joignent `role` (`ur.Id_Role = r.Id_Role`, `r.Nom`) ; `schemaRoles()` (cache `information_schema`) détecte l'ancien schéma (`role.Code` PK, `utilisateur_role.Role` = nom) tant qu'EA98 ne l'a pas migré, `sqlNomRoleUr($pdo, $ur, $r)` renvoie `[JOIN, expression du nom]` pour le SQL ad hoc, `idsRoles()` convertit nom → `Id_Role` (rôle inconnu = `RuntimeException`), `insererRoleUtilisateur()` écrit une ligne selon le schéma — **un seul `estPrincipal = 1` par utilisateur**, garanti par le code (`enregistrerRolesUtilisateur()`). L'ancienne colonne `utilisateur.Role` (ENUM) n'existe plus : voir « Database conventions ». Fonctions (`config/app_config.php`) : `rolesUtilisateur($pdo, $id)` (principal en tête, puis `Priorite`), `rolePrincipalUtilisateur()`, `rolesEffectifsCompte()` (rôles tels quels ; un cumul hérité JA + autres rôles est seulement journalisé), `rolesSession()` / `rolesDe($u)`, `aRole($roles, $u = session)` (au moins un des rôles), `estAdmin($u = session)` (`is_admin` ou rôle Administrateur), `menuDuRole($role)` (`role.RouteMenu`, repli `ROLES_REFERENCE` puis `nominateur-menu`), `rolesValides($pdo)` (noms de `role` par priorité), `libellesRoles($pdo)` (`[Nom => Libelle]`), `enregistrerRolesUtilisateur($pdo, $id, $roles, $principal)` (DELETE + INSERT, SANS transaction propre — à l'appelant ; principal ajouté s'il manque, vide = premier), `sqlARole($colId, $placeholder)` (fragment `EXISTS(… utilisateur_role …)` pour les requêtes ; jamais `utilisateur.Role` dans du nouveau SQL). Avant EA98 (`tableRolesExiste()` faux), toutes retombent sur la colonne `utilisateur.Role` si elle existe encore (`utilisateurAColonneRole()`). **Droits = union des rôles** : tous les filtres testent `aRole()` / `estAdmin()`, jamais `$_SESSION['utilisateur']['role']`. **Connexion directe** sur le menu du rôle principal (`AuthController::redirectForRole()` → `menuDuRole()`), sans page de choix ; les autres menus restent atteignables par URL selon les rôles. **Rôle `JA` exclusif (non cumulable)** : un compte JA a le seul rôle `JA`, un compte d'un autre rôle ne reçoit jamais `JA` (EA86 refuse tout jeu de rôles mêlant JA et un autre rôle, « Le rôle JA est exclusif ») ; les autres rôles restent cumulables entre eux. Un compte hérité qui cumule déjà JA et d'autres rôles en base n'est ni modifié ni bloqué (lignes `utilisateur_role` gardées, `rolesEffectifsCompte()` le journalise, `etatCompteJa()` le classe `ignore` pour EN15) ; EA86 le régularise (JA seul — fiche rattachée requise, `idJaDuCompteJa()` — ou sans JA : son `Id_Ja` devient alors sa fiche liée).

**Session revalidation (every auth filter).** `auth`, `adminauth`, `nominauth`, `csrauth`, `defiscauth`, `craconvocauth` and `jaauth` all go through `controlerSessionFiltre()` → `revaliderSessionUtilisateur($path)` (`config/app_config.php`, filters now also `require_once` it). At most once per `SESSION_REVALIDATION_DELAI` (60 s, `verifie_le`; missing = session opened before this version → revalidated at once) it re-reads `Login`, `Actif`, `ChangeLogin`, `PwdVersion` (only if the column exists, `utilisateurAPwdVersion()` cached `information_schema` check) and the roles (`rolesUtilisateur()`): row missing, `Actif = 0`, role set changed (`rôles modifiés`, compared sorted with session `roles`), `PwdVersion` ≠ session `pwd_version` or a JA account (role `JA`, exclusive) whose fiche can no longer be resolved by `idJaDuCompteJa()` (`Id_Ja` NULL — e.g. fiche deleted, FK ON DELETE SET NULL — or fiche missing; pre-EA98: no fiche of the same Id) (`fiche JA supprimée`), or — session in mode JA (`mode_ja`) — the session roles (`JA`) are NOT compared with the DB ones but `motifSessionModeJaInvalide()` checks the account's roles still equal `origine_roles` and its link still equals `id_ja` with an existing fiche (`idFicheJaLiee()`), or an old switched session (`origine_id`) → `detruireSessionNijac()` (`config/db.php`: data, file AND cookie, same cookie params as `demarrerSessionNijac()`) + redirect to `login`. A session without `pwd_version` adopts the current DB value, one without `roles` (opened before multi-rôles) gets them filled in; `is_admin` is recomputed from the roles (always false in mode JA); `ChangeLogin = 1` in DB is copied into the session; DB unreachable → no destruction (logged), retried next request. So EA86 deactivation / deletion / role change takes effect within a minute with nothing else to do. Then, while `change_login` is true, only `ROUTES_CHANGE_LOGIN` (`changer-mot-de-passe`, `logout`, `changer-compte` — `retour` only) pass — every other filtered route redirects to E006 (full page, with a POST « Se déconnecter » button in forced mode). The role-argument mechanism of `Auth` (`auth:CSR,CRA Convoc`) is unchanged and checked after revalidation.

**`utilisateur.PwdVersion`** (`INT UNSIGNED NOT NULL DEFAULT 0`, after `ChangeLogin`, created by `initTableConfiguration()`, EA98): incremented on every password change — E006 (then `session_regenerate_id(true)` and the new version + `change_login = false` written to the current session, which stays valid), E008 reset, EA86 « Écraser » (`sqlIncrementPwdVersion()` / explicit UPDATE). Copied into the session at login (`colonnesSessionUtilisateur()` + `construireSessionUtilisateur()`). Column missing (pre-EA98) → no version check, everything else works.

**Brute-force limits** (all in the flock'd `logs/login_attempts.json`, path from `tentativesFichier()` — constant `NIJAC_FICHIER_TENTATIVES` overrides it for CLI tests; timestamps of every key are kept `TENTATIVES_RETENTION_MINUTES` = 24 h, each check filters on its own window): `login:<ip>` (config `login_rate_limit_*`, 5 / 15 min); `login_compte:<login>` (typed login, trimmed + lower-cased, cut at 64 chars, unknown logins included — no existence oracle; 10 password failures / 60 min, same « Trop de tentatives » message, checked before the password); `mfa_essai:<id>` (wrong E010 codes, 20 / 24 h, checked at E001 before sending a code and at E010); `mfa_envoi:<id>` (code sends, 6 / 15 min); `mdpreset_ip:<ip>` (E007, 5 / 15 min, identical neutral answer beyond) + `mdpreset:<id>` (3 / 15 min); `mdp_actuel:<id>` (E006 current-password failures, `login_rate_limit_*`, CleanController pattern); `totp:<id>` (échecs de code TOTP / de code de secours / d'activation EA99, `login_rate_limit_*`). E001 runs `SecurePasswordHasher::verify($pwd, SecurePasswordHasher::HASH_FACTICE)` (constant PBKDF2 hash, same format/iterations) for unknown or inactive logins, so response time does not reveal existing accounts. E007 sends the reset email AFTER the HTTP response (`register_shutdown_function` + `fastcgi_finish_request()` when available, else `Connection: close` + `Content-Length` + flush; dev-mode redirection and error logging unchanged).

**Logout** is `POST logout` (global CSRF; menu « Se déconnecter » links submit a hidden `#form-logout`, E010 « Annuler » is a `formaction` button) and destroys session + cookie. `GET logout` (old bookmarks) only redirects to `login` and destroys nothing. `GET login` no longer drops a pending 2FA (`mfa_attente`); only a new login POST or logout does.

**E008 token key** = current password hash . `OBFUSCATOR_SEED` . `'|reset-mdp|'` . `getObfuscatorPepper()` (`cleJetonResetMdp()`). With an empty pepper the key is exactly the old one (old links still valid, but no gain: only the hash secrecy protects it); once the pepper is set, only the new key is accepted (links issued in the previous hour are lost).

**Double authentification par email (E001 → E010).** After a valid password, `AuthController` does **not** create `$_SESSION['utilisateur']`: it regenerates the session id and stores only `$_SESSION['mfa_attente'] = ['id', 'debut', 'hash', 'emis', 'essais', 'envois']` (password_hash of the code, never the code itself), emails a 6-digit code to `utilisateur.Email` and redirects to E010 (`login/code`, `login/code/renvoi`). ### Access control convention

- Every auth filter first revalidates the session against the DB (at most once a minute: `Actif`, roles, `Login`, `PwdVersion`) and enforces the forced password change (`change_login` → only `changer-mot-de-passe` / `logout`) — see "Session revalidation" above. New filters must call `controlerSessionFiltre()` the same way.
- **Multi-rôles : droits = union des rôles de la session.** Every role check (filters and controllers) goes through `aRole([...])` / `estAdmin()`, never `$_SESSION['utilisateur']['role']` (= principal only, used just for the post-login redirect and the « retour menu »). Below, « role X » means « X ∈ session `roles` ».
- Admin-only routes: `['filter' => 'adminauth']` in `Routes.php`
- Nominateur + admin routes: `['filter' => 'auth']` in `Routes.php` — plain `auth` (no argument) lets through **only `Administrateur` and `Nominateur`** (and `is_admin`); an account holding none of them (`CSR`, `Defiscalisateur`, `CRA Convoc`, `JA` only) is redirected to `login`.
- JA-only routes (E011 `ja-menu`, EJA2 `ja/disponibilites*`, EJA4 `ja/frais*`): `['filter' => 'jaauth']` — role `JA` required (`aRole('JA')`, see `JaAuth.php`; deliberately NOT granted by Administrateur alone, unlike `csrauth`/`craconvocauth`: these screens act on the session's own fiche `ja`, an admin has none and uses EN11/EN14/EN28). The fiche is ALWAYS the `utilisateur.Id_Ja` of the account `$_SESSION['utilisateur']['id']` for a pure JA account (`idJaDuCompteJa()`, pre-EA98 fallback: same Id), or `$_SESSION['utilisateur']['id_ja']` in mode JA (non-JA account with `utilisateur.Id_Ja`, see « Linked JA fiche »), re-checked by the filter AND by every JA controller through `idJaCompteSession()` (role `JA` + fiche re-read in DB, else 0 = refused); every nomination/rencontre id received from the client is checked as belonging to that fiche.
- **Each non-nominator role is limited to its own menu's screens**: CSR → E004/ES31/ES32/ES33 (`csrauth`), Defiscalisateur → E005/ED51–ED55 (`defiscauth`, ED53 unfiltered with in-controller check), CRA Convoc → E009/EC71–EC75 (`craconvocauth`), JA → E011, EJA2–EJA4 (`jaauth`) — pure JA account or non-JA account in mode JA. A shared `auth` route that one of those menus depends on lists the extra roles as filter arguments: `['filter' => 'auth:CSR,Defiscalisateur,CRA Convoc']` (`Auth.php`: allowed = Administrateur + Nominateur + arguments; spaces inside a role name are fine). Current declarations:
  - `changer-mot-de-passe` GET/POST → `auth:CSR,Defiscalisateur,CRA Convoc,JA` (E006 modal / toolbar link on every menu, E006 button on E011; `ChangerMotDePasseController` returns each role to its own menu, `JA` → `ja-menu`).
  - `messagerie/data/(:segment)` GET, `messagerie/(:segment)` PUT → `auth:CSR,CRA Convoc` (ES32 reads/updates message n°6 — `MessagerieController::isCsr()` restricts the CSR to it; EA93 from E009 for CRA Convoc).
  - `messagerie`, `messagerie/data`, `messagerie/(:segment)/dupliquer` POST, `messagerie/(:segment)` DELETE → `auth:CRA Convoc` (EA93 from E009 — `isCraConvoc()` restricts it to « CRA Convocation … » messages). `POST messagerie` (create) stays plain `auth` (refused to CRA Convoc by the controller anyway).
  Any new shared endpoint called from an E004/E005/E009 screen must get the matching argument; the controller keeps doing the fine-grained role filtering.
- EN14 (`nomination*`), EN26 (`stats-nomination*`) and EN28 (`suivi-nomination*`) routes: `['filter' => 'nominauth']` — role `Nominateur` or `Administrateur` (or `is_admin`) only, see `NominateurAuth.php` (no arguments), same pattern as `csrauth` (native session, redirect to `login` otherwise): `CSR`, `Defiscalisateur` and `CRA Convoc` are refused. No other screen calls these URLs in AJAX (EN26 is only linked from EN14, links back to it and only calls `stats-nomination/data`).

- **2FA TOTP des écrans CHAUTARD (EA96, EA97, EA98 ; activation / saisie sur EA99).** Les `guardChautard()` de `FfttTestController`, `BugSpidController` et `DbAdminController` appellent, après le contrôle du login, `App\Libraries\TotpChautard::controlerAcces('fftt-test'|'bug-spid'|'db-admin')` : 2FA non activée ou session non déverrouillée → redirection vers `securite-totp?retour=…` (GET) ou JSON `{ok:false, totp:true, url, msg}` (AJAX / POST ; `retour` filtré par la liste blanche `TotpChautard::RETOURS`). EA99 = `TotpController` (routes GET `securite-totp`, POST `securite-totp/activer|verifier|secours`, filtre `adminauth` + login CHAUTARD vérifié dans le contrôleur, vue `totp_index.php`, QR code de l'URI `otpauth://` dessiné par `asset/js/nijac-qrcode.js` — encodeur maison, sans CDN ; bouton EA99 dans l'onglet DBA de E002). RFC 6238 (SHA-1, 6 chiffres, 30 s, ±1 pas), fonctions pures et constantes `TOTP_*` dans le bloc « 2FA TOTP » de `config/app_config.php`. Activation = mot de passe **et** premier code valide (secret proposé gardé chiffré en session 15 min) → 8 codes de secours affichés une seule fois. Session déverrouillée 30 min glissantes : `$_SESSION['totp_ok_ts']` (+ `totp_ok_id`), prolongée à chaque accès, détruite avec la session. Une fois déverrouillée, aucun code TOTP n'est redemandé : EA98 `sql` / `charger-fichier-sql` / `supprimer-fichier-sql` redemandent seulement le mot de passe (`verifierMdpRequete()`) ; le code de secours se saisit sur EA99. Colonnes `utilisateur.TotpSecret` (secret base32 chiffré AES-256-GCM, clé = SHA-256(`TOTP_SEL_CLE` + pepper `getObfuscatorPepper()`)), `TotpDernierPas` (anti-rejeu, `UPDATE` conditionnel), `TotpSecours` (JSON de 8 codes hachés `password_hash`, usage unique) créées par `initTableConfiguration()` (EA98) ; colonnes absentes (`utilisateurATotp()`, cache `information_schema`) → accès SANS TOTP, journalisé `[NIJAC][SEC]` une fois par session (sinon EA98 ne pourrait pas les créer). Limitation `totp:<id>` dans `logs/login_attempts.json` (`login_rate_limit_*`). Journal `[NIJAC][SEC] TOTP …` sans code ni secret. Changer le pepper rend le secret illisible → déverrouillage par code de secours, ou procédure d'urgence SQL : `UPDATE utilisateur SET TotpSecret=NULL, TotpDernierPas=NULL, TotpSecours=NULL WHERE Login='CHAUTARD';` (la prochaine ouverture d'EA96/97/98 renvoie vers l'activation EA99).
- Security headers: the root `.htaccess` sends (`mod_headers`) `X-Frame-Options: SAMEORIGIN`, `X-Content-Type-Options: nosniff` and `Content-Security-Policy: frame-ancestors 'self'` (anti-clickjacking); whether the host honours them in production is to be checked.
- Public (tokenized or fully open) routes have no filter at all in `Routes.php` — e.g. EN18 `desiderata-club`, EN19 `adresse-ja`, EN21 `convocation-ja`, EN22 `disponibilite-ja`, EC74 `dispo-cra` (JA's answer to a CRA availability request, Obfuscator token + pepper, plain form POST with `csrf_field()`) (all JA-facing screens; session checked manually in-controller only to let Nominateur/Admin reuse them from their own menu)

### Database conventions

- No auto-column-add: columns are assumed to exist. New columns are added by an explicit `ALTER TABLE` per environment, or through `initTableConfiguration()` via EA98. The old per-controller `DESCRIBE`/`SHOW COLUMNS` + conditional `ALTER TABLE ADD COLUMN` guards have been removed.
- `initTableConfiguration($pdo)` (`config/app_config.php`, called only by EA98) also (re)creates schema constraints idempotently — currently the FKs `equipe.Division` / `equipe_nationale.Division` → `division.Division` (`fk_equipe_division` / `fk_equipenat_division`, `ON UPDATE CASCADE` / `ON DELETE RESTRICT`). `division` has PK `Division`; `rencontre` reaches it only via `equipe`.
- Auto-enum-extend pattern: `ajouterValeurEnum($pdo, $table, $colonne, $valeur, $defaut)` in `config/app_config.php` adds a value to an existing `ENUM` column if missing (re-reads the current definition via `SHOW COLUMNS` first, so no existing value is lost; KEEPS the column's current `DEFAULT` and `NULL`/`NOT NULL` read by `SHOW COLUMNS` — `$defaut` is only a fallback when the column has no readable default in the list, and is dropped if not in the list, so the ALTER can't fail on it) — used for `messagerie.Type` only (new system message types, e.g. `assurerTemplateExpirationFfttApi()`). Roles are no longer an ENUM: the former `assurerRoleCsr()` / `assurerRoleDefiscalisateur()` / `assurerRoleCraConvoc()` / `assurerRoleJa()` are removed; a new role = a row in `role` (+ `ROLES_REFERENCE` for the seed / fallback). The CSR role (ES31) doesn't get its own message type: it reuses `Id_Messagerie = 6` (Réengagements), the same message already sent by EN12 — see `MessagerieController::ID_MESSAGE_CSR`.
- Roles: tables `role` + `utilisateur_role` (see « Multi-rôles » above), created by `assurerRolesUtilisateurs()` (called by `initTableConfiguration()`, EA98, idempotent, each step in its own `try/catch` + `error_log`): `role` created (`Id_Role` schema) and seeded (`INSERT IGNORE`, `ROLES_REFERENCE`, then `UPDATE … Priorite` for `PRIORITES_ROLES_FORCEES`), `utilisateur_role` created (`Id_Utilisateur` type/collation copied from `utilisateur`, `Id_Role INT UNSIGNED`). **Migration from the old schema** (`role.Code` PK, `utilisateur_role.Role` = name): FKs pointing to `role` dropped, `role.Id_Role` added in one ALTER (rows kept and numbered, `UNIQUE uq_role_nom`), `Code` renamed `Nom`; `utilisateur_role.Id_Role` added (nullable) and filled by a join on `role.Nom = Role`; ONLY if every row is resolved: FKs dropped, then one ALTER (`Id_Role NOT NULL`, PK `(Id_Utilisateur, Id_Role)`, index `Id_Role`, `DROP COLUMN Role`); finally `assurerClesEtrangeresRoles()` (re)creates the FKs matching the resulting schema (so a failed step gets its FKs back). Any failure is logged and leaves the previous state, read by the fallbacks (`schemaRoles()`). Then, while `utilisateur.Role` exists, each user without a row gets his old `Role` as principal (`estPrincipal = 1`); the column (and its FKs / indexes) is DROPPED only when no user with a non-empty `Role` remains unmigrated (unknown code in `role`) — otherwise it is kept and logged, and EA98 retries next time. Pre-EA98 tolerance: every role helper falls back on `utilisateur.Role` (`tableRolesExiste()` / `utilisateurAColonneRole()`, cached `information_schema` checks). Never read nor write `utilisateur.Role` in new code.

Set to `NOW()` only after a successful send; an UPDATE failure is only `error_log`ged, the send stays a success (returned as `date_demande`). Added by `initTableConfiguration()` (EA98); same tolerance as `rencontre.Forfait` via `rencontreADateDemandeClub()` (cached `information_schema` check) — EN14 `data()` returns `NULL AS DateDemandeClub` if missing. EN14 list shows « Arbitrage club — demande envoyée le JJ/MM/AAAA » (`bi-envelope-check`) instead of « demande à envoyer », refreshed locally after a send from the panel. One send per rencontre from EN14: `demanderJaClub()` refuses (« Une demande a déjà été envoyée le JJ/MM/AAAA pour cette rencontre. ») when the date is set (column present) and the panel keeps `#ac-envoyer` disabled with « Demande déjà envoyée le JJ/MM/AAAA »; EN28 « Relancer le club » can always resend (`envoyerDemandeJaClub()` unchanged).
- `club_salle` (`Id_Club` same type/collation as `club.Id_Club`, `Id_Salle`, `EstPrincipale TINYINT(1) NOT NULL DEFAULT 0`, PK `(Id_Club, Id_Salle)`, index `Id_Salle` + `(Id_Club, EstPrincipale)`, FKs to `club`/`salle` `ON DELETE CASCADE ON UPDATE CASCADE` — created without FKs, indexes only, if the engine refuses them, logged) = many-to-many club ↔ salle, the ONLY source of truth for a club's salles and its salle principale (at most ONE per club: guard `definirSallePrincipale()`, a single `CASE WHEN` UPDATE). `salle.Id_Club` / `salle.EstPrincipale` are **obsolete**: kept in the DB, no longer read nor written once `club_salle` exists — never use them in new code. Created by `assurerTableClubSalle()` (called at the end of `initTableConfiguration()`, EA98, idempotent `CREATE TABLE IF NOT EXISTS`, fallback without FKs). `colonnesReferencantSalle()` lists every reference to a salle (declared FKs to `salle` + any `Id_Salle` column, incl. `rencontre.id_Salle`). Pre-EA98 tolerance: `clubSalleExiste()` (cached `information_schema` check, like `nominationAF131()`); every caller goes through helpers that fall back to the old columns when the table is missing: `sqlJoinSallePrincipale($colClub, $alias, 'LEFT JOIN'|'JOIN')` (replaces every former `LEFT JOIN salle s_c ON s_c.Id_Club = ed.Id_Club AND s_c.EstPrincipale = 1`, link alias `cs_<alias>`), `sqlIdSallePrincipale($colClub, $repliPremiere)` (used by `sqlSalleEffective()`), `sqlJoinSallesClub()` + `sqlColPrincipale()`, `sqlNbSallesClub()`, `sqlIdsSallesClub()`, `sallesDuClub()`, `liensClubsSalles()`, `lierClubSalle()`, `delierClubSalle()`, `trouverOuCreerSalle()` (insert, then reuse an existing salle at the same place via `sallesMemeLieu()` — EA81 FFTT sync, EN27 sync), `nbReferencesSalle()` (EA81 delete refused while referenced).

### Email mode

`etat_logiciel` config key controls routing: `Developpement` → all emails redirect to the `email_developpement` address. Always call `getEmailDestinataire($email)` before sending, never use raw addresses. Use `getNijacMailer()` from `config/app_config.php` to get a pre-configured PHPMailer instance — never `new PHPMailer` directly: it returns a `NijacMailer` (`Classes/NijacMailer.php`), the central guarantee. In `Developpement` mode it replaces every address passed to `addAddress`/`addCC`/`addBCC`/`addReplyTo` by `email_developpement` (once, PHPMailer deduplicates; display name kept unless it contains an `@`), records the replaced real addresses in a `X-NIJAC-Dev-Original-To` header (max 500 chars), and in `preSend()` prefixes the subject with `[DEV → n adresse(s) réelle(s)] ` unless it already contains `[DEV`. `setFrom` is untouched. A blank `email_developpement` in dev mode throws (« Mode Développement actif mais email_developpement non configuré : envoi bloqué ») instead of sending. In production it behaves exactly like PHPMailer. Existing `getEmailDestinataire()` calls stay (idempotent). Deliverability (anti-spam): `getNijacMailer()` sets From = config `smtp_from` (fallback `nijac@ligue-normandie-tt.fr`, never another domain), `Sender` (Return-Path) = From, `Hostname` (EHLO / Message-ID) = the From's domain, `XMailer = ' '` (no X-Mailer header — `NijacMailer` itself also redeclares `public $XMailer = ' '`, so even a direct `new NijacMailer()` sends no X-Mailer); every `AltBody` must be built with `altBodyDepuisHtml($html)` (config/app_config.php — drops head/style/script, block ends → line breaks, entities decoded) and only for an HTML body — its output never has more than one blank line in a row (none at start/end, no trailing spaces/NBSP; multi-cell table rows → one `libellé : valeur` line, http links → `texte : url`, mso conditionals/comments excluded, `\n` endings normalized to CRLF by PHPMailer); `NijacMailer` shares one SMTP connection per request (`SMTPKeepAlive`, closed at shutdown — each message is still a fresh instance, so nothing accumulates) and spaces consecutive `send()` calls by ≥ 0.3 s, so loops need no pause of their own. Never put hidden text in an email template (no `display:none` / `mso-hide:all` preheader at the top of the body): anti-spam filters flag it. No HTML comments (`<!-- … -->`) in email templates (code defaults or `messagerie.Message` bodies) — flagged as a spam signal; only functional Outlook conditionals (`<!--[if mso]>…<![endif]-->`, `<!--[if !mso]><!-->…<!--<![endif]-->`) are allowed. No DKIM in code: DKIM signing and the DMARC record (`_dmarc`, none today) must be enabled at the host (securemail.pro), SPF is `include:spf.webapps.net … ~all`.

### Obfuscator usage

```php
require_once __DIR__ . '/../../../Classes/Obfuscator.php'; // from ci4/app/Controllers/
$o = new \Obfuscator(OBFUSCATOR_SEED, getObfuscatorPepper());
$token = $o->obfuscate($idJa);    // URL-safe 8-char string
$idJa  = $o->deobfuscate($token); // returns -1 if invalid
```

Requires PHP `bcmath` extension. Used to expose JA IDs in public convocation/disponibilité/adresse URLs without leaking real PKs. `OBFUSCATOR_SEED = 167` is a fixed constant, documented in this file — it is **not** a secret (anyone with the source can recompute `obfuscate($id)` for any ID from it alone). The actual secret is the optional second constructor argument, `getObfuscatorPepper()` (`config/db.php`, ROT47-decoded from `.env`'s `OBFUSCATOR_PEPPER`, same pattern as `getFfttAppId()`/`getSmtpUser()`): when set, it's mixed into the seed derivation, making tokens unforgeable without it. Empty pepper (no `.env` entry) falls back to the pre-pepper behavior byte-for-byte — always call the constructor with both arguments so a configured pepper actually takes effect; passing `OBFUSCATOR_SEED` alone silently skips this protection.

### Menu button convention

Both menu views (`admin_menu_index.php` E002 and `nominateur_menu_index.php` E003) display a small screen code badge (top-right, `.btn-code` CSS class, `position: absolute`) inside each `.menu-btn`. Links now point to CI4 routes via `site_url(...)` instead of static filenames. When adding a new button to a menu, always include the `<span class="btn-code">EXXXX</span>` as the first child of the `<a>` element.

```html
<a href="<?= site_url('mypage') ?>" class="menu-btn btn-mycolor">
    <span class="btn-code">EN20</span>
    <div class="btn-icon"><img src="<?= base_url('img/myicon.png') ?>" alt="..."></div>
    <span>Titre du bouton</span>
    <span class="btn-desc">Description courte</span>
</a>
```
