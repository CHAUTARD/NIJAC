## Project overview

NIJAC is a PHP/MySQL web app for managing and nominating table-tennis referees (Juges-Arbitres, JA) for the Normandy League. Stack: PHP 8.2+, CodeIgniter 4, MySQL/MariaDB, Bootstrap 5, jQuery 3, no front-end build step.

The application is entirely implemented in `ci4/` (CodeIgniter 4). There is no more legacy stand-alone-PHP-page app — it was fully replaced by the CI4 port (see `git log` around "Version avec Ci4"). The repository root still holds shared, framework-agnostic pieces the CI4 app depends on: `config/` (`db.php`, `app_config.php`, `helpers.php`), `Classes/` (`Obfuscator.php`, `SecurePasswordHasher.php`, `Distance.php`), and `asset/` (CSS/JS served straight from the root, not from `ci4/public/`).

### FFTT API client

All FFTT calls go through `App\Libraries\FfttRawClient` (`ci4/app/Libraries/FfttRawClient.php`), instantiated via `getFfttRawClient()` (config/app_config.php), authenticated with `getFfttAppId()`/`getFfttAppKey()` (config/db.php, ROT47-decoded from `.env`). Plain PHP cURL, no Composer runtime dependency — production only has FTP access (no Composer, no shell), so this was a deliberate choice: any future change to this feature deploys like any other PHP file, no `vendor/` sync step.

Two ways to call it:

- **7 typed convenience methods** — `listClubsByDepartement()`, `retrieveClubDetails()`, `listOrganismes()`, `listEpreuves()`, `listEquipesByClub()`, `retrieveJoueurDetails()`, `listJoueursByClub()` — cover every FFTT call actually used by production screens (EN11, EN27, EA81, EA82, EA83). Each returns a plain associative array (or array of arrays) with the raw FFTT field names (e.g. `numero`, `nom`, `nomsalle`, `libequipe`) — no typed model objects.
- **`request(string $action, array $params = []): array`** — for any other raw endpoint: `xml_division`, `xml_result_equ` (poules/rencontres by division ID or `cx_poule`), `xml_chp_renc`, `xml_licence` (base SPID, distinct from `xml_licence_b`), or any field a convenience method doesn't surface (e.g. `xml_club_detail` returning multiple salles for one club — see `SalleController::ffttSync()`). `lastUrl()`/`lastHttp()`/`lastRaw()` expose the last request's details for diagnostics (see EA96).

Previously used the composer package `alamirault/fftt-api` (typed facade + Guzzle 6.x, an EOL branch with known CVEs) and, before that, `Classes/FfttApi.php` (raw cURL, a different `serie`/app-key signing scheme) — both removed. EA96 (FfttTestController, `testViaLibrary()`) only exercises the 7 production-used methods; it no longer covers the old facade's diagnostic-only surface (classement, historique, parties, Elo-style virtual points, regex-parsed rencontre details, actualités...), none of which backed a real screen.

## Running locally

No build step. Requires WAMP (Apache + MySQL on port 3307).

```bash
composer install          # root: PhpSpreadsheet + PHPMailer, used by config/app_config.php
cd ci4 && composer install # ci4/: CodeIgniter 4 framework itself
```

Access via `http://nijac/` — a dedicated WAMP vhost whose `DocumentRoot` is this folder directly (see `httpd-vhosts.conf` and the Windows `hosts` file), matching `app.baseURL` in `ci4/.env` (`http://nijac/`). Do **not** use `http://localhost/NIJAC/` (default vhost, NIJAC as a subfolder): `Config\App::$baseURL` has no path segment, so every `site_url()`/`base_url()` link generated while browsing under that host is wrong (wrong host under the default vhost, or wrong path if the host is added to `allowedHostnames`) — CodeIgniter's `SiteURI` only swaps the host for allowed hostnames, never the base path, so the two access methods can't both work against a single static `baseURL`. In production the app is deployed under a path (`https://www.ligue-normandie-tt.fr/nijac/`), so `ci4/.env`'s `app.baseURL` there must include that path — that `.env` is a separate file edited directly on the server (FTP-only deploy, see below), not the one in this repo. The root `.htaccess` transparently forwards everything to `ci4/public/index.php` (the CI4 front controller) except real files/folders (`asset/`, `img/`, `logs/`, `ci4/` itself), which are served as-is — except `.env*` (any location), `SQL/` (DB backups, read only server-side by `CleanController`) and `Importation/` (import drop folder, read/written only server-side), all explicitly denied since nothing in the app serves them over HTTP and they contain secrets/PII. No `RewriteBase` is hard-coded, so the same `.htaccess` works whether this folder is a vhost docroot (WAMP) or a subfolder (production).

The DB schema migrations run via `config/app_config.php → initTableConfiguration()`, no CI4 migration files are used. Only `DbAdminController` (EA98) calls it, so a new column/table gets created the first time an admin loads the EA98 screen after deploying a change — not automatically on every page load like before. The former per-controller inline `DESCRIBE`/`ALTER TABLE ADD COLUMN` self-healing checks (e.g. `DesiderataClubController` for `salle.Cp`, `JugearbitreController::ensureFfttColumns()`) have been removed: every column is assumed present in the DB. Adding a new column now means an explicit `ALTER TABLE` on each environment (or via EA98). Two exceptions remain: `ajouterValeurEnum()` still extends `ENUM` columns at runtime (`messagerie.Type`, `utilisateur.Role`), and a handful of import controllers still create their own indexes/FKs and `CREATE TABLE IF NOT EXISTS competition_regionale` (with its seed) inside a guarded `try/catch`.

No test suite exists for the application itself (`ci4/tests/` is the untouched CodeIgniter starter scaffold).

## Architecture

### Request lifecycle

Standard CodeIgniter 4 MVC: `ci4/app/Config/Routes.php` maps each URL to a `Controller::method`. Every controller extends `BaseController` and requires the legacy shared config files itself in its constructor (see below) — there's no bootstrap/autoloaded global include. Most screens are still dual-mode in spirit: one `index()` action renders the HTML view, and sibling actions (`data`, `store`, `update`, `delete`, ...) serve AJAX, mirroring the old "one file, `$action` dispatch" pattern but split into real controller methods and real routes instead of a single `$_POST['action']` switch.

### Key shared files (root, outside `ci4/`)

| File | Role |
|---|---|
| `config/db.php` | PDO singleton (`getPDO()`), env detection (WAMP vs production via `NIJAC_ENV` or `.env.production`), `rot47()` decoding of DB/SMTP/FFTT secrets from `.env` |
| `config/app_config.php` | DB migrations (`initTableConfiguration()`), all config helpers (`getConfig()`, `getDeptActifs()`, `getDepartementsAutorises()`), PHPMailer factory (`getNijacMailer()`), rate-limit helpers |
| `config/helpers.php` | Misc shared helpers used by a handful of controllers (adresse/commune/salle lookups) |
| `Classes/Obfuscator.php` | Bi-directional integer ↔ 8-char token (bcmath + Knuth multiplicative hash, seed = `OBFUSCATOR_SEED = 167` + secret pepper from `getObfuscatorPepper()`) — used to expose JA IDs in public URLs without leaking real PKs |
| `Classes/SecurePasswordHasher.php` | bcrypt wrapper — use `::hash($plain)` and `::verify($plain, $hash)` |
| `Classes/Distance.php` | GPS distance calculation between two lat/lon points |
| `tools/rot47.php` | Standalone CLI (`php tools/rot47.php valeur`) to pre-compute a ROT47-encoded value to paste into `.env` — not called by the app itself; the `rot47()` function it demonstrates is duplicated inside `config/db.php`, which the app does use |

Every CI4 controller pulls in `config/db.php` (and most also `config/app_config.php`, some also `config/helpers.php`) via `require_once __DIR__ . '/../../../config/xxx.php';` in its constructor — that relative path is `ci4/app/Controllers/` → repo root.

### Key CI4 files

| File | Role |
|---|---|
| `ci4/app/Config/Routes.php` | All routes; each screen's block is commented with its `EXXXX` code and access rule |
| `ci4/app/Config/Filters.php` | Filter aliases (`auth`, `adminauth`, `csrf`, ...) and globals — `csrf` filter is applied globally to all POST/PUT/PATCH/DELETE |
| `ci4/app/Config/Security.php` | CSRF config — `csrfProtection = 'cookie'` (double-submit, no CI4 session dependency), `regenerate = false` (stable token per session, screens fire multiple sequential AJAX POSTs), header name `X-CSRF-Token` |
| `ci4/app/Config/Database.php` | CI4 DB config — does **not** define its own credentials; `require_once`s the root `config/db.php` and copies `DB_HOST`/`DB_USER`/`DB_PASS`/`DB_NAME`/`DB_CHARSET`/`DB_PORT` into `$default` (single source of truth for DB config stays in the legacy file) |
| `ci4/app/Filters/AdminAuth.php` | Redirects to `login` unless `$_SESSION['utilisateur']['is_admin']` is true. Starts the session with **native** `session_start()`, not CI4's Session service — CI4's `FileHandler` names session files `PHPSESSID<id>` (vs PHP's own `sess_<id>`), so using CI4's service would silently stop sharing sessions with anything reading the raw `$_SESSION` global the same way the old app did |
| `ci4/app/Filters/Auth.php` | Redirects to `login` unless authenticated (Administrateur, Nominateur or CSR — there is no JA session, see Session structure below) |
| `ci4/app/Controllers/BaseController.php` | Empty CI4 starter base — no shared NIJAC logic lives here (that's why every controller requires the config files itself) |

### View / header convention

There is no shared header/layout partial (no equivalent of the old `includes/page_header.php`). Each view file (`ci4/app/Views/xxx_index.php`) is a full standalone HTML document that inlines its own `<head>`, its own `#page-header` markup (title, `EXXXX` badge, back link via `site_url(...)`), and its own `<style>` block. New screens should copy the header block from an existing view (e.g. [region_index.php](ci4/app/Views/region_index.php)) rather than trying to factor it out.

The CSRF token is exposed via `<meta name="csrf-token" content="<?= csrf_hash() ?>">` in every view's `<head>`, and `asset/js/nijac-csrf.js` reads that meta tag to inject the `X-CSRF-Token` header on jQuery AJAX calls.

### AJAX pattern

All AJAX endpoints return `['ok' => true/false, ...]` as JSON (`$this->response->setJSON(...)`). The JS side always checks `r.ok`. CSRF verification is handled globally by CI4's `csrf` filter (see `Config\Filters`) — controllers don't call anything themselves, unlike the old per-endpoint `csrfVerify(true)`.

### Session structure

Still plain PHP session (native `session_start()`/`$_SESSION`, not CI4's Session service — see `AdminAuth.php` above):

```php
$_SESSION['utilisateur'] = [
    'id'             => int,       // Id_Utilisateur
    'login'          => string,
    'nom'            => string,
    'prenom'         => string,
    'role'           => 'Administrateur' | 'Nominateur' | 'CSR' | 'Defiscalisateur' | 'CRA Convoc',
    'is_admin'       => bool,
    'id_departement' => string,    // e.g. '76'
    'change_login'   => bool,      // forces password change on next login
    'email'          => string,    // Utilisateur.Email — Reply-To + Cc prefill in Centre d'envoi (EN15)
];
```

**Double authentification par email (E001 → E010).** After a valid password, `AuthController` does **not** create `$_SESSION['utilisateur']`: it regenerates the session id and stores only `$_SESSION['mfa_attente'] = ['id', 'debut', 'hash', 'emis', 'essais', 'envois']` (password_hash of the code, never the code itself), emails a 6-digit code to `utilisateur.Email` and redirects to E010 (`login/code`, `login/code/renvoi`). Filters only look at `$_SESSION['utilisateur']`, so a pending session is unauthenticated. On a valid code: `session_regenerate_id(true)`, `mfa_attente` dropped, user re-read from DB, `$_SESSION['utilisateur']` created exactly as before (`change_login` flow therefore comes after the 2nd factor). Rules live in pure functions of `config/app_config.php` (`genererCodeSecurite()`, `hacherCodeSecurite()`, `emettreCodeSecurite()`, `verifierCodeSecurite()`, `peutRenvoyerCode()`, constants `CODE_SECURITE_*`: 10 min, 5 tries, 60 s between sends, 3 sends / 10 min); every wrong code also counts as a failed login for the IP (`enregistrerEchecLogin()`), plus a per-account send cap (`mfa_envoi:<id>`, 6 / 15 min, file-based). Email = system message of Type `Code de sécurité` (`TYPE_MESSAGE_CODE_SECURITE`, HTML body « Proposition A – Bleu institutionnel » held in a nowdoc, marker `{CODE}`, Cc/ReplyTo 0; sent with `isHTML` + clean plain-text `AltBody` by `rendreMessageCodeSecurite()`/`AuthController::envoyerCode()`, a plain-text body is still accepted and sent as text), seeded by `assurerModeleCodeSecurite()` (EA98; creates the system row only if missing, never overwrites), read via `resoudreModeleMessagerieParType($pdo, TYPE_MESSAGE_CODE_SECURITE, 0)` (system row only) with fallback `corpsParDefautCodeSecurite()` when the row doesn't exist yet (login works before EA98); admin-only in EA93 (no personal copy), excluded from EN15. Kill switch: config key `double_authentification` (`'1'` default/absent, `'0'` = password only, logged `[NIJAC][SEC]` on each login), seeded by EA98, editable in EA91 (0/1 validated). Emergency SQL when nobody can log in (SMTP down, wrong address): `UPDATE configuration SET valeur = '0' WHERE cle = 'double_authentification';`. `utilisateur.Email` is mandatory (EA86 client + server validation); an account without a valid email is refused at login while 2FA is on.

The array is built by `construireSessionUtilisateur()` (`config/app_config.php`), shared by the login (`AuthController::ouvrirSession()`) and by EA86 `UtilisateurController::update()`, which rewrites it from the DB when an admin edits their OWN account (department change without logout; never for another user; own role/Actif are locked by a guard so no inconsistent state). No perimeter cache exists: `getDepartementsAutorises()` re-reads config on every call.

There is no `JA` role/session: a JA never logs in. All JA-facing screens (EN19, EN21, EN22) are public routes, identified by an Obfuscator token (`?ja=TOKEN`) in a link emailed to them — see `construireMarqueursMessage()` in `config/app_config.php` for how those links are built.

### Access control convention

- Admin-only routes: `['filter' => 'adminauth']` in `Routes.php`
- Nominateur + admin routes: `['filter' => 'auth']` in `Routes.php` (role `CSR` also passes this filter, though it has no menu link into these screens)
- CSR-only routes (E004, ES31): `['filter' => 'csrauth']` — role `CSR` or `Administrateur` (see `CsrAuth.php`). EN12 briefly moved to `csrauth`/the CSR menu (E004) when the CSR role was introduced, then moved back to `auth`/the Nominateur menu (E003); its E003 cartouche has since been removed — the `desiderata-clubs` route stays on `auth` but is no longer menu-linked (réengagement flow lives on the CSR menu, ES31/ES32).
- Defiscalisateur-only routes (E005, ED51): `['filter' => 'defiscauth']` — role `Defiscalisateur` or `Administrateur` (see `DefiscalisateurAuth.php`), same pattern as `csrauth`.
- CRA Convoc-only routes (E009, EC71, EC72, EC73, EC74 `cra-dispo*`, EC75 `cra-stats*`): `['filter' => 'craconvocauth']` — role `CRA Convoc` (ENUM value, with a space) or `Administrateur` (see `CraConvocAuth.php`), same pattern as `csrauth`.
- Admin-only AJAX actions within a shared controller: checked individually inside the method, same idea as before (e.g. `SalleController`/`JugearbitreController`/`MessagerieController` use route filter `auth` but gate specific write actions to admin in code)
- EA96 (FfttTestController) and EA98 (DbAdminController) extra restriction, checked manually in the controller: `$_SESSION['utilisateur']['login'] === 'CHAUTARD'`
- Public (tokenized or fully open) routes have no filter at all in `Routes.php` — e.g. EN18 `desiderata-club`, EN19 `adresse-ja`, EN21 `convocation-ja`, EN22 `disponibilite-ja`, EC74 `dispo-cra` (JA's answer to a CRA availability request, Obfuscator token + pepper, plain form POST with `csrf_field()`) (all JA-facing screens; session checked manually in-controller only to let Nominateur/Admin reuse them from their own menu)

### Database conventions

- No auto-column-add: columns are assumed to exist. New columns are added by an explicit `ALTER TABLE` per environment, or through `initTableConfiguration()` via EA98. The old per-controller `DESCRIBE`/`SHOW COLUMNS` + conditional `ALTER TABLE ADD COLUMN` guards have been removed.
- `initTableConfiguration($pdo)` (`config/app_config.php`, called only by EA98) also (re)creates schema constraints idempotently — currently the FKs `equipe.Division` / `equipe_nationale.Division` → `division.Division` (`fk_equipe_division` / `fk_equipenat_division`, `ON UPDATE CASCADE` / `ON DELETE RESTRICT`). `division` has PK `Division`; `rencontre` reaches it only via `equipe`.
- Auto-enum-extend pattern: `ajouterValeurEnum($pdo, $table, $colonne, $valeur, $defaut)` in `config/app_config.php` adds a value to an existing `ENUM` column if missing (re-reads the current definition via `SHOW COLUMNS` first, so no existing value is lost) — used for `messagerie.Type` (new system message types, e.g. `assurerTemplateExpirationFfttApi()`) and `utilisateur.Role` (`assurerRoleCsr()`, called from `UtilisateurController`). The CSR role (ES31) doesn't get its own message type: it reuses `Id_Messagerie = 6` (Réengagements), the same message already sent by EN12 — see `MessagerieController::ID_MESSAGE_CSR`.
- System message n°3 « Convocation » (EN14, `resoudreModeleMessagerie($pdo, 3, …)`, Sujet unchanged — personal copies are matched by Sujet) has an HTML default body held in code: `modeleHtmlConvocationJa()` (`config/app_config.php`, nowdoc — keep it a nowdoc so `{…}` markers stay literal), kept as the reference of the default body (no caller: the DB row, editable in EA93, is the one sent). Current layout: summary table Date / Compétition / Juge-arbitre / Club recevant / Adresse / Correspondant, then « Actions attendues » box (2 bullets), then button + fallback link, then closing sentence + signature.
- System message `Convocation clubs` (constant `TYPE_MESSAGE_COPIE_CONVOCATION_CLUBS`): copy of a JA convocation sent by EN14 (`NominationController::envoyerCopieClubs()`) to the correspondants/référents of both clubs. Identified by Type (no fixed Id), seeded by `assurerModeleCopieConvocationClubs()` from `initTableConfiguration()` (EA98; only if no system row of that Type exists, never overwrites) with HTML `modeleHtmlCopieConvocationClubs()` (JA phone/email via `{COORDONNEES_JA}`, an already-escaped HTML block, empty parts omitted; raw `{TEL_JA}`/`{EMAIL_JA}` also available) (subject used as-is, `Copie – ` prefix included, `Cc = 0`, `ReplyTo = 1`), resolved via `resoudreModeleMessagerieParType()` (personal copy first). Subject and body are sent as-is (no prefix/line added, no link filtering). Missing or empty → hard-coded fallback `modeleHtmlCopieConvocationClubs()` + `sujetParDefautCopieConvocationClubs()` (same subject as the seed), `Cc = 0`, `ReplyTo = 1`, so EN14 works before EA98 — message n°3 is never used for the clubs' copy. Editable in EA93 (saving a message of that Type containing `{URL_CONVOCATION_JA}`/`{LIEN_CONVOCATION}` returns a non-blocking `avertissement`, shown as a warning toast — no cleanup), not exposed in EN15.
- No validity notion on `nomination`: an existing nomination is always valid (no manual validation step since EN14's « Valider les nominations » button was removed; removing a JA deletes the nomination). The former `nomination.Valide` column is dropped by `initTableConfiguration()` (EA98, idempotent, FKs/indexes on it dropped first, best-effort); no code reads or writes it any more, so the app works before and after that migration — never reintroduce it. Former `Valide = 0` rows (club arbitrations before migration) are plain nominations.
- `nomination.AccuseReception` (`DATETIME NULL`, after `EmailEnvoye`) = date/time the JA acknowledged his convocation on EN21 (POST `convocation-ja/accuse`, idempotent, first date kept; NULL = not yet). Added by `initTableConfiguration()` (EA98). Exception to "columns are assumed present": EN21 and EN28 read it only if `nominationAAccuseReception()` (config/app_config.php, cached `information_schema` check) says it exists, so they keep working before EA98 runs. Logic in `accuserReceptionConvocation()` / `convocationAccusable()` (same file): only the link's own nomination (it must exist). EN21 date rules (`D` = `rencontre.Date`, `J` = `jourConvocation()` = PHP `date('Y-m-d')` for both rules, never MySQL `CURDATE()`), pure functions in `config/app_config.php`, enforced server-side and driving the view: acknowledgment only if `J <= D` (`dateConvocationAccusable()`); expenses entry (`sauvegarderFrais()`, via `ConvocationJaController::etatSaisieFrais()` → `fraisSaisissables()`) only if `J >= D` (before: « La saisie des frais sera possible à partir du JJ/MM/AAAA. »); dependency kept on the match day only: `J = D` → expenses require the acknowledgment when it's missing (column present); `J > D` → free entry; column missing (pre-EA98) → no acknowledgment condition. ### Email mode

`etat_logiciel` config key controls routing: `Developpement` → all emails redirect to the `email_developpement` address. Always call `getEmailDestinataire($email)` before sending, never use raw addresses. Use `getNijacMailer()` from `config/app_config.php` to get a pre-configured PHPMailer instance — never `new PHPMailer` directly: it returns a `NijacMailer` (`Classes/NijacMailer.php`), the central guarantee. In `Developpement` mode it replaces every address passed to `addAddress`/`addCC`/`addBCC`/`addReplyTo` by `email_developpement` (once, PHPMailer deduplicates; display name kept unless it contains an `@`), records the replaced real addresses in a `X-NIJAC-Dev-Original-To` header (max 500 chars), and in `preSend()` prefixes the subject with `[DEV → n adresse(s) réelle(s)] ` unless it already contains `[DEV`. `setFrom` is untouched. A blank `email_developpement` in dev mode throws (« Mode Développement actif mais email_developpement non configuré : envoi bloqué ») instead of sending. In production it behaves exactly like PHPMailer. Existing `getEmailDestinataire()` calls stay (idempotent). Deliverability (anti-spam): `getNijacMailer()` sets From = config `smtp_from` (fallback `nijac@ligue-normandie-tt.fr`, never another domain), `Sender` (Return-Path) = From, `Hostname` (EHLO / Message-ID) = the From's domain, `XMailer = ' '` (no X-Mailer header — `NijacMailer` itself also redeclares `public $XMailer = ' '`, so even a direct `new NijacMailer()` sends no X-Mailer); every `AltBody` must be built with `altBodyDepuisHtml($html)` (config/app_config.php — drops head/style/script, block ends → line breaks, entities decoded) and only for an HTML body — its output never has more than one blank line in a row (none at start/end, no trailing spaces/NBSP; multi-cell table rows → one `libellé : valeur` line, http links → `texte : url`, mso conditionals/comments excluded, `\n` endings normalized to CRLF by PHPMailer); `NijacMailer` shares one SMTP connection per request (`SMTPKeepAlive`, closed at shutdown — each message is still a fresh instance, so nothing accumulates) and spaces consecutive `send()` calls by ≥ 0.3 s, so loops need no pause of their own. Never put hidden text in an email template (no `display:none` / `mso-hide:all` preheader at the top of the body): anti-spam filters flag it. No HTML comments (`<!-- … -->`) in email templates (code defaults or `messagerie.Message` bodies) — flagged as a spam signal; only functional Outlook conditionals (`<!--[if mso]>…<![endif]-->`, `<!--[if !mso]><!-->…<!--<![endif]-->`) are allowed. No DKIM in code: DKIM signing and the DMARC record (`_dmarc`, none today) must be enabled at the host (securemail.pro), SPF is `include:spf.webapps.net … ~all`.

### Obfuscator usage

```php
require_once __DIR__ . '/../../../Classes/Obfuscator.php'; // from ci4/app/Controllers/
$o = new \Obfuscator(OBFUSCATOR_SEED, getObfuscatorPepper());
$token = $o->obfuscate($idJa);    // URL-safe 8-char string
$idJa  = $o->deobfuscate($token); // returns -1 if invalid
```

Requires PHP `bcmath` extension. Used to expose JA IDs in public convocation/disponibilité/adresse URLs without leaking real PKs. `OBFUSCATOR_SEED = 167` is a fixed constant, documented in this file — it is **not** a secret (anyone with the source can recompute `obfuscate($id)` for any ID from it alone). The actual secret is the optional second constructor argument, `getObfuscatorPepper()` (`config/db.php`, ROT47-decoded from `.env`'s `OBFUSCATOR_PEPPER`, same pattern as `getFfttAppId()`/`getSmtpUser()`): when set, it's mixed into the seed derivation, making tokens unforgeable without it. Empty pepper (no `.env` entry) falls back to the pre-pepper behavior byte-for-byte — always call the constructor with both arguments so a configured pepper actually takes effect; passing `OBFUSCATOR_SEED` alone silently skips this protection.
